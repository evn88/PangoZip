# Фоновые размеры папок и процент сжатия

После получения списка архива приложение запускает отдельную задачу для расчёта всех папок. Итеративный обход снизу вверх складывает непосредственных потомков: каждый узел обрабатывается за O(1), весь расчёт — O(n). Исходное дерево не меняется; результаты сохраняются только для папок. Распаковка и чтение содержимого файлов не нужны. Поисковый фильтр не влияет на суммы.

Колонка «Размер» и сведения о папке используют один результат: сумму несжатых размеров всех вложенных файлов. До завершения расчёта ячейки папок показывают «…», а выбранная папка — индикатор ожидания. После завершения таблица обновляет колонки размеров и процентов одним обновлением; дальнейшая отрисовка ячейки читает готовое значение. Файлы и их метаданные доступны сразу.

Открытие другого архива, обновление после редактирования и закрытие отменяют предыдущие задачи и дожидаются отмены. Поколение расчёта предотвращает публикацию старых данных, включая обновление снимка с прежним UUID. Пустая папка имеет размер 0; переполнение суммы оставляет соответствующее значение неизвестным.

«Сжатие» показывает экономию: `(1 - размер_в_архиве / исходный_размер) × 100%`. Например, 1000 → 250 байт означает 75%, а 1000 → 1250 байт означает −25%. Для папки используется сумма размеров файлов. Если хотя бы один вложенный файл не имеет достоверного packed size, процент папки неизвестен. Нулевой исходный размер также даёт прочерк. Shared solid-блоки не распределяются между файлами: при неизвестных размерах отображается «—». Колонка остаётся видимой, а подсказка заголовка объясняет смысл отрицательных значений.

## Замеры 18 октября 2026

Реальный ZIP, созданный bundled 7zz из 20 000 файлов в 201 папке, debug-сборка, один холодный прогон:

| Этап | Время |
| --- | ---: |
| Создание тестового архива | 17,28 с |
| Чтение списка через 7zz | 9,59 с |
| Парсинг списка | 3,73 с |
| Построение дерева | 552 мс |
| Расчёт всех папок | 32,5 мс |

Синтетическое дерево из 100 000 файлов в 1001 папке: debug-агрегация 252 мс, удерживаемая дополнительная память около 480 КиБ. Оптимизированный `swiftc -O` с тем же helper и моделями, пять прогонов: медиана агрегации внутри `Task.detached` **16,916 мс**, медиана непосредственного создания дерева 29,582 мс. Во всех прогонах проверены суммы raw/packed, количества и экономия 75%. Оптимизированный замер исключает чтение архива, парсинг, построение дерева сервисом и отрисовку UI. Значения зависят от компьютера и структуры архива.

Временные benchmark-тесты и файловые фикстуры удалены. Регрессионные тесты покрывают автоматический расчёт без выделения, реальные ячейки, пустые/виртуальные папки, неизвестный packed size, переполнение, отрицательное сжатие, отмену и обновление с прежним UUID.

## Проверка интерфейса

На macOS 27 через CUA проверена отдельная сборка с этими исходниками. В ZIP до выделения строки размеры и проценты уже видны: корень 88 КБ / 81,1%, вложенная папка 5 КБ / 99%. Сведения вложенной папки показывают точные 4500 байт и один файл. Пустой файл показывает прочерк процента, несжатый Store — 0%, повторяющийся текст — 99,6%. В реальном solid-архиве ML.7z (5879 объектов) корень без выделения показывает 884,8 МБ; колонка «Сжатие» остаётся видимой с прочерком. Заголовки находятся ниже панели инструментов. При недостаточной ширине доступна штатная горизонтальная прокрутка.

Проверки выполняются в изолированной копии HEAD с изменениями только этой задачи: параллельная работа над Quick Look меняла build/config-файлы в основном checkout. Исходники и тесты сравнены побайтово с основной рабочей копией. `swift test`: 63 Core + 30 App, без ошибок тестов; AppKit выдаёт системные предупреждения Contacts XPC. Строгий Swift Format, сборка приложения и `codesign --verify --deep --strict` проходят.
