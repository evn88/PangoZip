# Обновления из GitHub Releases

PangoZip использует [Sparkle 2.10.0](https://github.com/sparkle-project/Sparkle/releases/tag/2.10.0) для загрузки, проверки и безопасной установки новых версий из `evn88/PangoZip`. Автоматическая проверка включена по умолчанию, выполняется примерно раз в сутки и отключается в настройках. Проверку можно запустить вручную. Загрузка и установка требуют подтверждения пользователя в стандартном окне Sparkle; скрытая установка при выходе отключена.

## Что проверяется

Адрес ленты зафиксирован в приложении: `https://github.com/evn88/PangoZip/releases/latest/download/appcast.xml`. Лента и DMG подписаны Ed25519. Открытый ключ находится в `SUPublicEDKey`; закрытого ключа в приложении и репозитории нет. `SURequireSignedFeed` запрещает неподписанные метаданные, а `SUVerifyUpdateBeforeExtraction` проверяет архив до распаковки. Контрольная сумма SHA-256 остаётся доступной для ручной проверки, но не заменяет цифровую подпись.

Sparkle сравнивает `CFBundleVersion`, учитывает macOS 26+ и архитектуру arm64, устанавливает проверенную копию приложения и перезапускает его. Версия сборки обязана увеличиваться при каждом выпуске. PangoZip откладывает финальную подготовку до завершения очереди архивных операций и работающих фоновых помощников. Перед запуском установщика необходимо закрыть другие экземпляры PangoZip; проверка повторяется перед перезапуском. Отказ закрыть изменённые файлы отменяет текущий перезапуск. Sparkle может сохранить подготовленную копию до следующего штатного выхода; в этом случае выход также ожидает закрытия других экземпляров и завершения фоновых помощников. Без подготовленного обновления обычный выход не зависит от отдельных помощников Finder.

Бесплатная подпись Ed25519 обеспечивает подлинность обновления относительно установленной копии PangoZip. Она не является Developer ID или нотариализацией Apple: существующие ограничения Gatekeeper для первой установки ad hoc сборки сохраняются. Приложение не меняет настройки защиты macOS.

## Выпуск

1. Влить проверенные изменения в `main`. Workflow **Release from main** автоматически повышает patch-версию и номер сборки всех компонентов.
2. Дождаться workflow: он собирает DMG, подписывает и проверяет ленту, атомарно сохраняет коммит версии с тегом, затем публикует все три файла после проверки загруженных артефактов. Порядок восстановления после сбоя описан в [автоматическом выпуске](github-releases.md).
3. Для подписи workflow использует секрет репозитория `PANGOZIP_SPARKLE_PRIVATE_KEY`. Без него выпуск завершается ошибкой. Секрет передаётся официальному `generate_appcast` через stdin, не через аргументы команды. В publish job закрытый ключ не передаётся.

Для локальной подготовки после сборки DMG:

```sh
python3 scripts/release_metadata.py prepare vX.Y.Z --signing ad-hoc
```

Локально инструменты читают ключ из Keychain с account `app.pangozip.desktop`. Существующий ключ нельзя заменять при обычном выпуске: пользователи доверяют открытому ключу своей установленной версии. Храните резервную копию закрытого ключа в защищённом месте. Экспорт через официальный `generate_keys -x` содержит секрет и не должен попадать в Git, логи или командную строку.

`release_metadata.py` создаёт ленту во временной папке только с текущим DMG, проверяет подписи официальным `sign_update` и проверяет точные URL, размер, SemVer и номер сборки. `publish-release.py` сверяет SHA-256 всех трёх артефактов, содержимое ленты, удалённый тег и подтверждённые GitHub digest до отметки Latest.

## Первая версия и проверка

Версии до первого выпуска с updater, включая 0.6.1, не умеют обновляться автоматически. Первую версию с updater нужно установить вручную. Наличие `appcast.xml` в следующем опубликованном Latest обязательно; до этого ручная проверка может показать сетевую ошибку 404.

Для полного испытания нужны две реальные сборки с одним открытым ключом, увеличенным номером сборки и опубликованной подписанной лентой. Проверяются успешное обновление и перезапуск, отказ при изменённом DMG/ленте, ожидание архивных операций и отмена закрытия изменённого файла. Локальные unit tests проверяют блокировку/отмену подготовки, конфигурацию доверия, проверки ленты и порядок подписи компонентов; они не заменяют это испытание установщика.

Официальные инструкции: [подключение и безопасность Sparkle](https://sparkle-project.org/documentation/), [публикация обновлений](https://sparkle-project.org/documentation/publishing/), [программная интеграция](https://sparkle-project.org/documentation/programmatic-setup/).
