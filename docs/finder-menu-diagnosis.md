# Диагностика отсутствующего меню Finder

Дата: 2026-10-13.

## Подтверждённое состояние

Установленный `/Applications/PangoZip.app` версии 0.6.0 (10) прошёл `codesign --verify --deep --strict`. Расширение подписано ad hoc, имеет App Sandbox и доступ к выбранным пользователем файлам. Проверка `pluginkit -m -Av -i app.pangozip.desktop.finder` вне песочницы Codex изначально вернула `no matches`. Другие Finder Sync расширения (Keka, Google Drive) присутствовали.

Прямой вызов `pluginkit -a` для встроенного установленного appex восстановил одну активную запись со знаком `+`. Команда `-e use` не применялась; пользовательский выбор включения не менялся. Повторная проверка после сборки подтвердила сохранение записи. Почему исходная запись исчезла, по доступным журналам установить не удалось.

Следовательно, платная подписка не понадобилась для восстановления регистрации на этом Mac. Это не подтверждает совместимость ad hoc сборки со всеми компьютерами. Developer ID предназначен для распространения вне Mac App Store и доступен участникам платных программ Apple: https://developer.apple.com/help/glossary/developer-id-certificate/.

## Исправления кода

- Первый запуск раньше регистрировал только основное приложение и worker через Launch Services. Теперь явно добавляется установленное appex через `/usr/bin/pluginkit -a` с аргументами Process, без shell и принудительного включения.
- При временной недоступности bundle ветка `FinderSync.deliver` очищала наблюдаемые папки навсегда для текущего процесса. Теперь команда отклоняется, а следующая попытка снова проверяет приложение. Проверки удаления/корзины сохранены. Срабатывание прежней ветки на этом Mac не доказано.
- Добавлена read-only диагностика `scripts/check-finder-integration.sh`: проверяет подпись и активную запись конкретной установленной копии. Не перезапускает Finder, не регистрирует и не включает расширения.

## Проверки и ограничения

Регрессионный тест регистрации сначала показал две ошибки, затем прошёл. Полный `swift test`: 59 Core + 15 App, без ошибок. Строгая проверка формата Sources/FinderExtension/Tests/Package.swift и `scripts/build-app.sh` прошли. Независимый агент проверил изменённый код регистрации и сохранение наблюдения.

Установленная копия приложения не заменялась; восстановлена только её текущая системная регистрация. Новая сборка сохранена в build/PangoZip.app; для установки подготовлен локальный DMG.

После разблокировки Mac проверен реальный ПКМ:

- Локальный README.md в репозитории: основное меню PangoZip присутствует.
- Папка в Google Drive: основного меню PangoZip нет. Меню расширения Keka тоже отсутствует, но обе команды PangoZip присутствуют в подменю «Службы». Выполнение команд и загрузка облачных файлов не проверялись.
- Пользователь сообщает об отсутствии в iCloud и на рабочем столе. Finder подтверждает, что Desktop синхронизируется с iCloud. Автоматические щелчки на Desktop не открыли даже стандартное меню, затем инструмент сообщил `Sky Computer Use native pipe closed before response`; это ограничение проверки, а не доказательство поведения PangoZip.

Активная регистрация и запущенный процесс расширения не гарантируют появление меню во всех папках. В [документации Apple](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html) Finder Sync предназначен для наблюдаемых папок синхронизации, а не универсального изменения Finder. [Apple DTS](https://developer.apple.com/forums/thread/756711) отдельно описывает ограничения пересечения областей разных расширений и каталоги, в которых Finder Sync не работает. Это поддерживает гипотезу ограничения облачного контекста, но не доказывает общий запрет iCloud/Google Drive или конкретный конфликт на этом Mac.

Следующие различающие проверки:

1. Прочитать реальное меню Desktop/iCloud и сравнить с Google Drive и локальным файлом. Если стандартное меню не открывается инструментом, не интерпретировать это как отсутствие расширения.
2. При временной диагностической сборке логировать факт вызова `menu(for:)`, вид меню и количество выбранных URL без путей и имён файлов. Отсутствие вызова только в облаке укажет на маршрутизацию Finder; вызов с пустым выделением — на обработку выбора.
3. Только после этого проверять изменение наблюдаемых корней или обработку `targetedURL`. Добавление корней облачных провайдеров без такого сигнала может пересечь область их собственных расширений.

Облачное отсутствие пока не объявляется исправленным. Платная Developer подписка не является подтверждённой причиной: эта же установленная ad hoc сборка отображает меню на локальном файле.
